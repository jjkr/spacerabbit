# CGEvent Analysis: Three-Finger Workspace Swipe Gesture

## Overview

This document analyzes the CGEvent structures captured during a three-finger swipe gesture to change to the next workspace to the left on macOS. The events were generated by BetterTouchTool (BTT) with PID 1777 and show the complete sequence of a workspace switching gesture.

## Event Sequence Summary

The gesture produces a complex sequence of events that can be categorized into several phases:

1. **Initial Gesture Events** (Type 29) - Basic gesture tracking
2. **Workspace Switch Events** (Type 30) - Actual workspace switching with animation data
3. **Completion Events** (Type 29 with Field 110: 32) - Gesture completion and cleanup
4. **Final System Events** - Mouse clicks and keyboard events

## Key Event Types

### Type 29: Gesture Tracking Events
These events track the ongoing gesture without triggering workspace changes. They appear throughout the gesture sequence.

**Common Fields:**
- **Field 55 (0x37)**: Always `29` (0x1d) - Event type identifier
- **Field 40 (0x28)**: `1777` - Source PID (BetterTouchTool)
- **Field 53 (0x35)**: `3` - Likely finger count (three-finger gesture)
- **Field 58 (0x3a)**: Timestamp - Incremental timing
- **Field 169 (0xa9)**: Secondary timestamp or sequence counter

### Type 30: Workspace Switch Events
These are the critical events that actually trigger workspace switching with animation data.

**Key Fields:**
- **Field 55 (0x37)**: `30` (0x1e) - Workspace switch event type
- **Field 110 (0x6e)**: `23` (0x17) - Animation control flag
- **Field 123 (0x7b)**: `1` - Gesture enable flag
- **Field 132 (0x84)**: Progressive counter (1, 2, 4) - Animation phase
- **Field 134 (0x86)**: Copy of Field 132 - Animation phase confirmation
- **Field 135 (0x87)**: Encoded float values - Gesture delta as 32-bit float pattern
- **Field 138 (0x8a)**: `3` - Finger count confirmation
- **Field 165 (0xa5)**: `1` - Secondary enable flag

**Animation Data (Double Fields):**
- **Field 124 (0x7c)**: Primary swipe delta (0.012192 → 0.255478) - Horizontal movement
- **Field 125 (0x7d)**: Secondary delta - Vertical component or smoothing
- **Field 126 (0x7e)**: Tertiary delta - Often negative, possibly acceleration

## Gesture Progression Analysis

### Phase 1: Gesture Initiation
The gesture begins with Type 29 events tracking finger movement. No workspace switching occurs yet.

### Phase 2: Workspace Animation
Type 30 events begin appearing with:
- Field 132/134 starting at `1`, progressing to `2`, then `4`
- Field 124 (swipe delta) increasing from ~0.012 to ~0.255
- Field 135 containing encoded float patterns representing gesture velocity

### Phase 3: Advanced Animation
Later Type 30 events show additional fields:
- **Field 115/117 (0x73/0x75)**: `8` - Additional animation parameters
- **Field 164 (0xa4)**: `8` - Animation state confirmation
- **Field 129/130 (0x81/0x82)**: Position coordinates (3.002563)

### Phase 4: Gesture Completion
Events with Field 110: `32` indicate gesture completion and cleanup.

## Critical Field Patterns

### BetterTouchTool Detection Pattern
The log identifies BTT events using:
- Field 55: 29 or 30
- Field 110: 23 (for workspace events)
- Field 123 and 165: both set to 1
- Field 41: 0 (not the expected 0x81cf magic number in this case)

### Animation Progression
The workspace animation is controlled through:
1. **Field 132/134**: Animation phase counter (1 → 2 → 4)
2. **Field 124**: Primary gesture delta (increasing throughout)
3. **Field 135**: Encoded velocity/acceleration data

### Timing and Synchronization
- **Field 58**: Primary timestamp (nanoseconds)
- **Field 169**: Secondary timestamp, often slightly offset
- Events occur in rapid succession (~8ms intervals during active animation)

## Float Encoding in Field 135

Field 135 contains 32-bit float values encoded as 64-bit integers:
- `1011335168` (0x3c47c000) ≈ 0.012192 as float
- `1019625472` (0x3cc64000) ≈ 0.024200 as float
- Values increase throughout the gesture, representing velocity/delta

## Workspace Switching Mechanics

The actual workspace switch appears to be triggered by:
1. **Field 110**: Value `23` enables workspace animation
2. **Field 123/165**: Both set to `1` to enable gesture processing
3. **Field 132/134**: Progressive animation phases
4. **Field 124**: Accumulated gesture delta reaching threshold

## Event Timing Analysis

- **Total gesture duration**: ~670ms (from first to last Type 30 event)
- **Event frequency**: ~8-16ms intervals during active animation
- **Animation phases**: 3 distinct phases (1, 2, 4) with increasing complexity

## Conclusion

The three-finger workspace swipe generates a sophisticated event sequence with:
- Continuous gesture tracking (Type 29)
- Progressive animation control (Type 30)
- Multiple delta/velocity calculations
- Phase-based animation progression
- Precise timing coordination

This analysis reveals that macOS workspace switching involves complex animation state management with multiple redundant fields for reliability and smooth visual transitions.
